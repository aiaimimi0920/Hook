# 二维码投射

二维码投射将一台 Windows 电脑上贴图或 Art 的正式图像，持续同步为另一台运行
Hook 的电脑上的关联贴图。数据方向为发送端到接收端；接收端保留自己的位置、
尺寸、透明度、裁剪和本地标注。

## 使用

“被投射”二级栏的数据流向仅展示投射端设置，不展开选项。点击“导入投射”，
在贴图内的紧凑弹窗选择二维码图片（PNG）或粘贴投射链接，不再显示解释性标签和页脚。
来源地址在本地解析后显示，
点击“导入”才连接服务，读取当前版本并接收为关联贴图；失败可在弹窗中重试。
右侧继续显示投射来源标识，版本数字按钮已移除。

### 选择设备投送（共享 Loom，无需官方账号）

1. 两端在同一 Loom 完成设备配对。Hook 自动跟随当前 Loom；接收端从托盘打开
   “接收二维码投射”可暂停或恢复参与。自动接受、提示确认、自动拒绝及黑白名单
   在 Loom 的设备管理 → 投射规则中配置，不需要在 Hook 另填接收地址。
2. 发送端选中图块，Ctrl+E → 投射，在二级栏的设备/设备组下拉中勾选目标即可投射，
   取消勾选即可取消投射。二级栏不再保留独立的发送和关联按钮。
   设备与组的重复成员只发送一次；设备组、其他 Loom 的连接由 Loom 配置。
   本功能明确采用“投送并持续同步”，发送端后续编辑会更新接收贴图。
   行尾标记显示处理中（…）、成功（✓）或失败（!），悬停查看详情，失败可点击重试。
   收到接收端显示回执或远端解除确认后才显示成功；邀请已创建和取消已排队仍为处理中。
   关闭下拉不取消操作。设备、设备组、用户图标不显示数量，点击箭头展开；
   目标逐行显示 ID 和勾选框，长列表支持滚轮及滚动条拖动。用户下拉提示服务
   尚未开放；连接和设备组均在 Loom 配置。组开关操作当前成员，重叠成员不会重复投射；
   单设备和相关组的勾选状态同步变化，部分成功或部分不可用不会显示全组成功。
3. 接收端按策略自动显示，或在桌面中央偏上显示独立的接受/拒绝提示。可稍后处理，
   同一邀请不会因轮询反复弹出，仍可回到接收面板处理。提示不抢占已打开的投射面板。
   保存并呈现后，发送端显示“接收端已显示”。
4. 接收端离线或关闭功能后，在线目录最多保留 30 秒。共享 Loom 邀请约 4 分 30 秒后失效。
   切换工作区后会重新读取当前 Loom 上下文；旧工作区的迟到结果不会写入新工作区。

只有获准配对且启用了接收的 Hook 才会出现在目录。此流程不使用官方登录、
好友或会员服务。协议详见 Loom 的 protocol/STICKER_DELIVERY.md。

### 两端连接各自的 Loom（离线互信）

管理员在 Loom 的设备管理 → 投射连接中查看双方公开身份并双向配置信任，也可用
`scripts/Invoke-LoomOfflinePeer.ps1`。Hook 各自在自己的 Loom 配对并自动跟随它。
发送端仍从 Ctrl+E 的投射面板刷新设备，选择标注所属 Loom 的远端设备；接收端
可确认、拒绝或自动接收，之后持续同步并支持停止。无需官方账号或官方服务器。

这种关联独立保存自己的 Loom 路由，不改写发送端签名邀请，不生成可用于共享
Loom 的二维码。任何对等配置变更都会使该 Loom 的既有离线关联失效；完成配置
后重新投送。设备禁用再启用不会恢复旧关联。协议和限制见 Loom 的
`protocol/OFFLINE_PROJECTION_PEERS.md`。

### 二维码或复制邀请

1. 打开 Ctrl+E 编辑栏的“投射”，或贴图右键菜单/Art 参数面板的“二维码投射”。
2. 默认使用“共享 Loom（无需账号）”：本机 Loom 开启后，Hook 使用本机发现清单中的
   凭据自动注册自己的设备身份并创建邀请，无需先手动批准本机 Hook、登录账号或
   检查另一端是否在线。已禁用或拒绝的身份仍需在 Loom 中恢复授权。
   二维码和链接声明邀请的服务地址，不保证其他电脑能访问该地址；接收时才连接
   对应 Loom 并验证设备权限。可读取当前 Loom 配置，手动地址仅用于此关联，
   不修改全局设置。远程地址禁止明文 HTTP、凭据、路径、查询参数和 fragment。
   也可显式选择“Loom 账号联网”，沿用两端本机 Loom 登录同一账号的 v2 路径。
3. 接收端从托盘打开“接收二维码投射”。粘贴邀请内容，或先截取二维码、运行
   官方 OCR 能力的二维码识别，再选择面板中的识别结果。
4. 读取邀请后先确认显示的共享 Loom 或账号服务，再验证来源并取得图像预览。
   选择“接收为关联贴图”完成关联；Hook 中没有额外的中心账号登录步骤。
5. 发送端修改图像，或 Art 产生新的正式图像后，接收端自动更新。关闭面板继续同步。
   从关联贴图打开投射面板，可以停止投射或解除关联，保留最后图像。

共享 Loom 邀请使用发送端时间加 4 分 30 秒，为服务端的 5 分钟上限保留 30 秒时钟余量。
这不替代系统校时；时钟偏差过大时仍会拒绝邀请。v2 邀请仍沿用服务端期限。
接收后的关联不受邀请有效期限制。过期邀请需要在发送端
移除已停止的关联，然后重新生成。一个邀请只绑定一个接收设备和一个贴图。

v2 二维码中的中心地址必须与 Loom 已登录的服务匹配。Hook 只请求本机 Loom，
账号凭据与 Loom 设备私钥由 Loom 保管，不进入 Hook、二维码或贴图会话。
Loom 退出或登录失效时，Hook 保留最后图像并提示前往 Loom 登录。

## 内容和网络范围

普通贴图通过现有导出链合成 PNG，包含裁剪、图像编辑及标注；Art 使用现有导出链
取得正式图像。接收端无需安装或执行对应 Art。不支持实时视频、纯文本 Art、
交互式 Surface 的运行状态和手机浏览器接收；没有图像的节点会显示不可投射提示。

共享 Loom 模式使用 v1，设备认证与服务转发无需官方账号。设备管理授权仍然必需。
v2 使用中心协调与 Iroh 传输。已有 relay 配置用于受信任部署实验，不代表官方
会员中继已实现；正式官方中继需要独立的服务端权益、接入鉴权和用量限制，尚未开放。
未配置中继的环境只能尝试直连；真实跨网与 UDP 受限条件仍需按部署环境验收。

新建及已有 v1 二维码和关联请求所选的共享 Loom HTTPS 服务，不会被解释为账号
登录地址。v1 的 `127.0.0.1`、`localhost` 和 `::1` 仍仅适用于同机验证。

## 双向标注编辑

共享 Loom 和互信跨 Loom 的 v1 关联支持在关联管理的数据流向设置中启用双向修改。
只有发起端能切换方向，所有目标共用同一模式；接收端显示权威方向。默认单向 PNG
关联保持原行为，账号模式 v2 不支持此编辑合同。

启用时 Hook 将底图与支持的标注分开，Loom 保存对象版本并合并不同对象的修改。
支持形状、线、箭头、文字、画笔、高亮和编号；马赛克、模糊及不支持的合成效果
会明确拒绝启用。位置和显示尺寸保持本地独立。会话期间底图固定，裁剪、基础图或
相关合成参数变化会暂停同步并提示错误，需要停止关联后重新创建。

同一对象的并发修改保留本地内容并显示冲突，可以选择保留本地修改并提交，或采用
远端状态。切回单向后接收端的未提交修改仍保留，但不能提交到远端。发送请求先
提交到独立 IndexedDB 编辑日志；回复丢失后重用原请求，重启时检查日志与工作区
是否一致，不把滞后的工作区保存静默覆盖到远端。源编辑日志丢失时明确要求恢复，
不从合成 PNG 猜测原始标注。

编辑日志最多 64 条，每条 8 MiB、合计 64 MiB；对象最多 256 个，每次提交最多
32 个变更。Loom 的回执和墓碑通过 source-only checkpoint 有界回收，旧模式和旧
基线请求随后被拒绝。清除 WebView 数据也会清除编辑恢复日志。

## 恢复与限制

定向多目标发送保存为 source-only projectionSenders，每张贴图最多 8 条。每个目标
独立显示进度、重试和停止；已成功保存的关联在再次发送时跳过。部分失败可重新
按发送按钮重试，成功目标不会被覆盖。定向发送在网络创建前将签名邀请、目标及原始
PNG 提交到 IndexedDB；重试先读取相同投射 ID，仅在明确不存在时重发原请求。
创建回复丢失后再次对账，刷新后仍复用原身份和图像，不因源图已编辑而另签邀请。
存储不可用、损坏或容量不足时停止创建，不退回无持久化发送。
原有二维码和接收端 qrProjection 关联继续可读；复制贴图不会复制这些活跃关联。

请求日志最多 64 条、估算 48 MiB，成功后保留至解绑，覆盖会话保存滞后时的目标重试。
“取消未完成投射”保留已有成功关联，持久标记其他请求并后台解绑；即使普通清理队列
写入失败，后台也会从 IndexedDB 恢复取消任务。确认解绑后才删除请求记录。
这不替代工作区会话保存，也不保证本机存储被清除后的请求恢复；旧二维码创建路径不在
此持久重试机制范围内。

关联元数据与贴图会话一同保存。Loom 持久化当前 PNG、待发布 PNG、来源 epoch
和接收绑定，后台按中心策略同步（默认 15 秒），重启后重新授权并恢复传输。
丢失发布响应时先对账中心版本，避免重复发布。快速修改合并为最新状态，每条
关联只有一个在途同步任务，错误退避最长 30 秒。复制贴图不会复制活跃关联。

显式停止时立即停止本地更新，离线期间保留待解绑状态；恢复网络后通知远端。
删除贴图或取消尚未完成的接收，会将解绑加入有界清理队列。队列保存在本机
WebView 存储中并在重启后重试；若本机存储不可写，只能在当前进程内重试。
更换工作区及退出会丢弃旧任务的迟到响应。

PNG 最多 4 MiB，宽高各最多 8192，总像素不超过 16,777,216。Loom 最多保存 64 条
记录、每个发送设备最多 8 条，总存储最多 48 MiB。每次更新至少间隔 500 ms。

## 验证边界

上述 Loom 管理、接收配置、多目标与双向标注属于 P3-P5 源码增量。2026-09-27
隔离候选完成 PC1/PC3 的共享/跨 Loom 接收策略、双向绘图、模式与冲突约束、
批量关联及停止保留验证，并保存物理桌面截图。批量场景使用 PC3 在两个 Loom
上的独立身份，传输使用固定 SSH 转发；未覆盖旧手动测试包或声明直接网络通过。
详细范围见 Neuro 根仓库 `docs/PROJECTION_PRODUCT_P6_VALIDATION.md`。以下保留
此前版本的原生证据来源。

自动化覆盖了接收前的两次确认、连续更新、合并、重试、停止、复制、会话恢复和
离线清理；native 校验响应身份、版本和 PNG 摘要。隔离 Loom HTTP 测试使用两个
独立 Ed25519 设备身份，覆盖配对、创建、接收、两次更新、重启和解绑，以及篡改、
过期、错误身份、撤销 epoch、容量和请求预算。

设备列表定向投送与接收策略已接入，聚焦测试覆盖自动/确认/拒绝、重复请求、
重启、撤销和保存失败。2026-09-26 已完成 PC1/PC3 两个原生 Hook、两个 release
Loom 的确认、自动、拒绝、编辑同步、停止、双方 daemon 重启及 Hook 会话恢复、
撤销与不可复活验证，并保存 PC3 物理桌面截图。发送入口使用 Ctrl+E 的远端设备
选择；跨机器链路使用固定主机密钥 SSH 转发。详见根仓库
`docs/STICKER_DELIVERY_S3_FULL_VALIDATION_2026-09-26.md`。好友与官方会员中继仍预留接口。

v2 另有真实 Iroh 双运行时检查，覆盖持久化、两次更新、丢失发布响应、账号隔离、
撤销与停止。Hook 覆盖 v1/v2 分流、未登录时禁止创建、v2 签名及更新确认校验。
完整命令和候选证据见根仓库的 `docs/QR_PROJECTION_V2_NATIVE_VALIDATION_2026-09-24.md`。

这些检查尚不能代替直接 LAN HTTPS、跨网 NAT、受限 UDP 中继回退、真实 OAuth
和完整 Windows 重启验收。
内部候选包保留 dirty 来源标记，不能作为已验收的公开发布版本。
