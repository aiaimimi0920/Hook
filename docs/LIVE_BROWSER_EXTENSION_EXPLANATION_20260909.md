# 当前 Live 截图是否需要浏览器扩展

是的。对于你要求的“网页滚动或切换标签后，仍持续显示原网页区域，特别是原
直播画面”，我们当前实现需要在你实际使用的 Edge profile 中启用 Browser
Live 扩展。仅运行 Hook、按 Ctrl+2，还不足以保证得到这种内容绑定的 Live。

我此前没有把这个必要依赖提前讲清楚，并且只在自动加载扩展的测试浏览器中
验证成功，没有完成你的日常浏览器接入。这是我的方案说明和交付存在缺口。

## 当前两种 Live 的区别

普通窗口 Live 不需要浏览器扩展。它绑定程序窗口里的某块位置，并持续获取
该位置的画面。程序窗口移动时可以跟随同一窗口，但网页内部滚动后，这个
位置显示的内容就变了；切换标签后，窗口显示的页面也变了。因此这种方式
无法保证你要求的原直播内容保持。

网页内容 Live 是本轮新增的路径。扩展在浏览器内部取得原页面和相关 iframe
的信息，把选区绑定到原内容；对于支持的视频选区，当前实现固定原 video
元素及视频内部的裁剪区域。之后读取的是这个已绑定的视频对象的画面。
滚动页面和切换其他标签不会自动把绑定对象换掉。

Ctrl+2 在当前设计里承担统一入口的作用，并不表示后端使用了同一种采集方式。
你最近的实际日志记录了 source=window，所以得到的是窗口 Live，确实无法
满足你反复强调的需求。

## 扩展究竟承担什么工作

扩展负责浏览器内的授权框选、识别和绑定原页面内容，以及提供后续画面。
Loom 负责连接浏览器能力，Hook 负责显示和管理 Live 贴图。

这是本机链路，这项功能不需要依靠云端才能成立。扩展必须加载到真正打开
直播间的那个 Edge profile；扩展文件放在磁盘上，或者在另一个测试 profile
中加载成功，都不代表你的日常浏览器已经接入。

## 是否从原理上只能使用扩展

不是。浏览器扩展是我们当前采用的接入方式，并非所有可能方案的唯一选择。
如果希望普通 Edge 不安装扩展，就需要另外实现并验证浏览器内部接入方式，
例如具有适当调试入口的浏览器，或者由应用管理的独立网页实例。这些方案会
带来不同的启动方式、登录态和页面一致性问题，不能说删除扩展就可以直接替代。

单纯观察普通浏览器窗口正在显示的像素，无法保证取得已经滚出视口或被其他
标签替换掉的原视频内容。要实现你的要求，当前方案需要进入浏览器内部绑定
内容，而不是仅靠窗口坐标持续取图。

因此，准确的当前状态是：普通窗口 Live 可以独立使用；你要求的网页内容
保持功能，在当前实现中依赖浏览器扩展。扩展启用之后也仍需完成你日常环境
的实际验收，不能把“装上扩展”直接等同于所有网页场景均已解决。
