# 二维码与条码识别开发计划

状态：**首版已实现（本地解码、展示、输出端口、会话持久化和发布包已接入；全量前端测试仍需后续拆分验证）**
范围：Hook 独立仓库；不修改 Loom、Neuro 根仓库或其他子项目。

## 1. 目标

为截图/贴图增加本地二维码与条码识别，并同时满足两类使用方式：

1. 普通用户可以查看、复制或确认后打开识别出的地址；
2. 识别结果可以作为结构化数据连接到后续 Art Node。

本计划不把地址保存在某个 UI 文本框中，而是将识别结果作为贴图的正式数据输出。

## 2. 已确定的交互方向

采用“统一识别入口 + 双视图展示”：

- `Ctrl+2`：统一识别当前内容，覆盖 OCR、二维码和条码；仍保留 `Alt+2` 作为 OCR 显示/隐藏。
- 截图或贴图识别完成后，在二维码/条码位置显示临时编号标记；不修改原始图片。
- 点击标记显示结果卡片：类型、内容、复制按钮、受控的“打开链接”按钮。
- `Tab` 属性面板显示持久的“识别结果”区域，适合查看多个结果、选择主结果和连接端口。
- 识别到多个码时，每个码有独立编号；`recognized_url` 表示当前选中的主结果，`recognized_codes` 保留全部结果。
- 任何网址都不得自动打开；初版仅对 `http`/`https` 提供打开操作，其余内容按文本复制。

## 3. 数据与工作流边界

### 3.1 共享识别核心

设计为无 UI、无副作用的本地服务：

```text
图片字节 -> CodeResult[]
```

每个结果至少包含：

- `format`：QR、Code128、EAN13 等；
- `text`：原始解码内容；
- `url`：能够安全分类为网址时填写；
- `bounds`：图片中的位置；
- `confidence` 或解码状态；
- 稳定的结果标识，供多码选择使用。

识别库候选为 ZXing 系列（Rust 版本优先），最终依赖必须在开发阶段完成许可证、供应链和 Windows 打包评估后再确定。

### 3.2 贴图数据

识别结果的完整结构作为贴图数据保存；面板和悬浮层都从该结构渲染。

同时暴露稳定的输出端口：

```text
recognized_url    text   当前选中的网址（没有网址时为空）
recognized_text   text   当前选中码的原始文本
recognized_codes  any    全部识别结果数组
```

URL 使用现有 `text` 端口类型，不新增专用 URL 类型。用户应从属性面板或结果卡片的输出端口拖线到 Art Node，而不是让 Art Node 读取 UI 文本或剪贴板。

## 4. 分阶段实施顺序

### 阶段 A：边界确认（已完成）

- 冻结上述交互、数据和快捷键语义；
- 记录当前 `Ctrl+2` OCR 行为，确保后续兼容；
- 确认输出端口、序列化、同步和下游参数解析路径；
- 已冻结快捷键、数据、同步和下游连接边界；实现继续严格限制在 Hook 仓库。

### 阶段 B：本地解码核心

- 引入并隔离条码解码库；
- 首批支持 QR、Code128、EAN-8/EAN-13、UPC-A/UPC-E、Code39、DataMatrix、PDF417；
- 支持旋转、缩放、灰度/对比度预处理和多码结果；
- 设置图片尺寸、结果数量和执行时间上限；
- 为每种格式和识别失败场景补充离线测试样本。

### 阶段 C：Hook 统一识别命令

- 将 `Ctrl+2` 从单纯 OCR 动作扩展为统一识别动作；
- 根据上下文识别当前选中的贴图，必要时进入框选识别模式；
- OCR 与二维码/条码结果并行保存，但互不覆盖；
- 识别失败时提供可重试结果，不阻塞截图完成。

### 阶段 D：结果展示

- 实现临时位置标记和结果卡片；
- 实现 `Tab` 属性面板中的“识别结果”区域；
- 单码、无码、多码、非 URL 内容分别处理；
- 复制不需要确认，打开链接必须明确点击并显示域名。

### 阶段 E：Art Node 数据连接

- 为贴图提供识别输出端口及可见性规则；
- 将 `recognized_url`、`recognized_text`、`recognized_codes` 写入现有输出映射；
- 保证链接在保存、加载、同步和重新识别后仍然有效；
- 为多码场景定义“当前主结果”与“全部结果”的一致语义；
- 增加从结果卡片快速进入连接模式的入口，但不复制另一套连接逻辑。

### 阶段 F：验证与发布准备

- 单元测试：格式解析、URL 分类、多码选择、输出值；
- 集成测试：截图 -> 识别 -> 面板/悬浮层 -> Art Node 参数；
- 安全测试：恶意 URL、非 HTTP scheme、超大图片、过多结果和识别超时；
- 运行 Hook 的 formatter、类型检查、Rust 测试、前端测试和有效行数检查；
- 只有用户明确要求开始开发并完成验证后，才构建 Hook release；本计划阶段不构建、不发布。

## 5. 暂不纳入首版

- 摄像头实时扫码；
- 自动打开网址；
- 云端识别或把图片发送给 Loom；
- 所有厂商私有码、全部邮政码和未经样本验证的工业变体；
- 让二维码识别结果直接触发下载、执行程序或其他外部副作用。

## 6. 完成判据

只有同时满足以下条件，才算该功能开发完成：

1. 普通用户可以从截图中识别并安全复制/打开二维码地址；
2. 条码结果可以正确显示类型和内容；
3. 多码结果可区分、可选择；
4. 识别结果可通过正式输出端口连接到 Art Node；
5. 重新加载工作流后结果和连线不丢失；
6. 相关测试、依赖安全检查和 Hook 发布验证全部通过。
