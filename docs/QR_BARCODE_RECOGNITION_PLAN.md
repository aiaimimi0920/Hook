# 二维码与条码识别能力说明

状态：**已迁移到 `neuro.official/ocr`，作为 OCR 功能包的子能力按需安装**
范围：Loom 提供签名能力包、运行时和安装生命周期；Hook 只托管通用命令、附件、覆盖层与通知。

## 1. 产品边界

二维码/条码识别与文本 OCR 共用一个可选能力包，而不是第二个独立插件：

- Loom 设置页的 **能力扩展** 区域下载、验证、授权、启用或卸载 OCR 包；
- OCR 包安装并启用后，贴图工具栏的 **OCR** 主菜单只提供缓存结果操作，
  不再重复提供手动二维码/条码识别子项；
- 图片字节只通过有界、调用期资源租约交给能力运行时；
- 解码、结果 Schema、覆盖层场景和复制命令都归能力包所有；
- Hook 核心不链接扫码库，不保留二维码业务组件，也不按插件 ID 分支。

停用或卸载 OCR 包后，文本模型和扫码库都不会再加载。已经保存的通用附件保持
opaque，可在以后重新安装兼容包后恢复渲染。

## 2. 当前交互

1. 选中包含图像的贴图并按 `Ctrl+2`；
2. 能力包在同一次调用中执行文本 OCR 与本地 QR/条码扫描，不再通过工具栏
   提供重复的手动扫码入口；
3. 结果写入 `neuro.official/ocr.codes.v1` attachment；
4. 绿色框显示码的位置，每个框中央显示一个操作圆；
5. 点击操作圆，在码附近显示二级面板；用户可以复制原始内容、关闭面板，或在结果为
   无凭据 HTTPS URL 时点击 **跳转**；
6. `Alt+2` 同步隐藏或显示文字 OCR 层和码层；
7. 识别数量、无码结果和复制结果都使用当前贴图右上角的可堆叠通知。

识别结果不会自动打开网址、下载文件或执行程序。只有用户点击二级面板的 **跳转** 后，
能力包才会返回通用 `external.openUrl` effect。Loom 运行时要求已授权
`hook.external.open` 和已消费的用户手势；Hook 还要求当前调用来自直接 Surface click，
再由原生命令复核无凭据 HTTPS URL 后交给系统浏览器。该代理适用于任何能力包，不包含
OCR 或二维码 ID 特判。

## 3. 数据合同

能力包输出的核心结构为：

```text
图片字节 -> CodeResult[] -> neuro.official/ocr.codes.v1 attachment
```

每个结果包含：

- `id`：一次结果内唯一的稳定标识；
- `format`：QR、Code128、EAN13 等解码格式；
- `text`：有界的原始内容；
- `url`：仅当内容可保守分类为无凭据 `https` 地址时出现；
- `points` 与 `bounds`：图片坐标系中的有界定位信息。

附件同时保存源图宽高、当前结果列表和声明式 `surfaceScene`。结果最多 32 个，单个文本
最多 16 KiB，定位点最多 16 个，整份附件不得超过 240 KiB。运行时拒绝空图、超大像素图
和不可读取的调用期资源。

当前版本不重新引入旧的 `recognized_url`、`recognized_text`、`recognized_codes` 核心端口。
能力驱动的图端口必须先成为通用、manifest-driven contribution，由任何第三方插件声明，
再以 attachment JSON pointer 绑定值；在该通用协议完成前，不允许为 OCR ID 增加固定端口。

## 4. 旧会话迁移

旧版 `UnitData.barcodeResult` 仍可能存在于真实用户会话中。Hook 加载会话时执行一次有界、
幂等迁移：

1. 完整校验尺寸、结果数量、字符串、点、边界和唯一 ID；
2. 生成 `neuro.official/ocr.codes.v1` 通用附件；
3. 让附件通过统一持久化 sanitizer；
4. 只有完整附件成功保留后才清空旧字段；
5. 无效、冲突、超预算或附件已占满时保留原字段，避免静默丢失。

迁移不会执行二维码内容，也不会因为保存旧数据而加载能力包。

## 5. 安全与资源约束

- 解码完全本地进行，不上传图片；
- 只读调用期 staging 文件，图片输入上限 16 MiB、像素上限 5000 万；
- 结果数、文本、点和附件总字节数均有硬上限；
- 只允许普通 `https` 元数据进入跳转路径，拒绝用户信息、空主机、控制字符、空白和反斜杠；
- 复制和通知由 Hook 的权限代理执行，能力进程不直接访问系统剪贴板；
- 外部打开要求显式权限、已消费手势、直接 Surface click，并由 Hook 原生边界再次解析；
- disable/uninstall 会取消并等待在途调用，再释放资源租约和运行时进程。

## 6. 验证矩阵

- QR fixture：识别文本、格式和几何；
- 纯文本、无码和损坏图片：有界失败且不阻塞 Hook；
- 超大图片、过长文本、过多结果：拒绝或截断在合同上限内；
- 旧 `barcodeResult`：成功迁移、幂等加载、无效数据保留；
- manifest：命令、菜单、data type、renderer、权限与运行时 ID 一致；
- 安装：签名 catalog 下载、SHA-256、包签名、SBOM、Provenance、权限批准与启用；
- 生命周期：停用、重启恢复、升级、回滚、卸载后无残留能力进程；
- 人工：真实贴图中扫描多个码，检查 `Alt+2` 同步显隐，并逐个验证中心圆、复制、关闭、
  HTTPS 跳转与非 HTTPS 不显示跳转。

摄像头实时扫码、云端扫码、自动打开网址以及未经样本验证的工业私有码不在当前范围内。
