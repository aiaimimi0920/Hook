# Live 截图需求收敛决定

2026-09-09，按用户明确决定，撤销以下需求：网页滚动或切换浏览器标签后，
Live 贴图仍保持显示原先选中的网页内容并持续更新。

理由：为这一能力引入浏览器扩展、独立网页实例或应用专用接入，会增加用户
使用成本，不符合本产品的日常截图交互目标。

## 保留的主线

用户使用 Ctrl+2 框选程序窗口中的区域，创建可持续更新、可移动并支持既定
交互能力的 Live 贴图。继续关注 DPI、普通贴图能力一致性、多路性能和资源
释放等已经明确的功能与质量要求。

源程序窗口移动时，选区仍跟随原窗口中的对应位置。源窗口内部的内容发生
变化，包括网页滚动或切换标签，Live 贴图允许显示这个区域变化后的画面。
不再要求保留被滚走或被其他标签替换的历史内容。

## 不再推进的工作

不再要求用户安装 Browser Live 扩展，不再为被撤销的需求安排接入、开发或
验收，也不再要求用户留出空闲时段测试这一能力。

这项需求属于用户主动撤销，不属于技术实现完成。此前相关失败与通过记录
作为历史证据保留，不能用于宣称被撤销的完整目标已经实现。

后续代码收敛已执行：Ctrl+2 直接进入原生 Live 选区，浏览器快捷键转发、
网页授权轮询、导入入口、文档捕获后端和浏览器专用分支已删除。Loom 的
Browser Live 候选包源代码与专属测试也已移除；通用扩展桥保留。

历史候选产物、浏览器注册信息和已安装的实验包没有被自动卸载。旧版本
可执行文件仍包含旧行为，应使用重新构建的候选版本。编译、聚焦测试和
headless smoke 已通过；本次没有重新进行交互式桌面验收或帧率基准测试。
