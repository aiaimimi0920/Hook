## 先说明入口，避免再次误导

本次接通的是 **Web Live: pin original webpage region** 专用入口：
发起一次命令，在浏览器扩展中框选，随后自动生成 Live 贴图。
不再需要“准备 → 框选 → 返回 Hook 再导入”。

**普通 Ctrl+2 仍然是程序窗口像素截图，不是网页文档截图。**
如果继续只用普通 Ctrl+2 框网页，它仍会跟随窗口当前显示的页面。
本次不能被描述为“普通 Ctrl+2 已经自动绑定浏览器标签”。
下面的网页入口是已有的候选路径，不应被当作普通 Ctrl+2 已修好的替代结论。

## 本机使用步骤

1. 运行本次 Hook：
   `<hook-repo-root>\..\release\Hook\browser-live-user-entry-20260908-r2\V0.2.29\portable\hook.exe`。
   如果已有旧 Hook，请先正常退出旧版本，避免单实例机制继续使用旧程序。
2. 在你日常使用的 Edge 中确认启用了 **Loom Browser Live (Candidate)**。
   如未启用，打开 `edge://extensions`，打开开发人员模式，选择“加载解压缩的扩展”，选择：
   `C:\Users\vmjcv\AppData\Local\Neuro\BrowserLive\extension`。
   可将该扩展固定到工具栏。无需重新安装另一个 Edge。
3. 在 Hook 中选中一个普通贴图，按 **Ctrl+Shift+P**，点击
   **Web Live: pin original webpage region**。
   如果画布为空，先用 Ctrl+1 创建一个普通贴图，作为现有扩展授权契约的发起目标。
4. Hook 会在该贴图的标准通知区提示你进行网页框选。点击“知道了”可以关闭提示，
   不会取消等待。在约 30 秒内切到目标网页，点击浏览器工具栏中的上述扩展，框选区域。
5. 选完会自动生成新的 Live 贴图，**不需要再打开命令面板导入**。
   该路径的设计是绑定原文档的原坐标区域；实际通过的场景、失败记录和限制见下文。

本机 Loom 中的新能力包已安装并启用。**自动化测试使用的是独立测试 Edge profile；
不能因此声称你的日常 Edge profile 已经启用了扩展。** 第 2 步是日常使用的必要检查。
浏览器权限只能由明确的扩展操作取得，不能用 Hook 的窗口截图手势冒充。
参见 [Chrome activeTab 权限说明](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)。

## 本次真正修改了什么

- Hook 的网页命令先准备服务，再有界等待浏览器选择；成功后自动创建 Live Unit。
- 等待只有一条串行查询链，约 30 秒超时；关闭 Hook、目标贴图删除/版本改变、
  能力包授权改变都会阻止继续采用选择。等待不创建捕获源，也不重复生成授权。
- 等待开始前记录选择序号，只接受之后的新选择，避免把上一次遗留选区自动导入。
  采用明确的 `browserGrantId`，不再在打开时任意取队列中的下一个选区。
- 浏览器返回的授权尺寸用于创建贴图，不把入口中的 1×1 占位尺寸当成实际大小。
- 内部准备/查询命令从命令面板隐藏，只保留一个可见网页入口。
- 导航或关闭原文档仍使绑定失效；不会自动改绑另一个页面。普通窗口捕获没有被替换。

## 实际验收：不是只跑 mock

最终候选使用真实编译的 Hook、当前正在运行的 Loom daemon、已安装并启用的签名
能力包、已注册的 native messaging host，以及本机 Edge 中实际加载的生产扩展。
测试通过真实命令面板发起一次命令，再通过生产扩展框选，最后检查实际 Live Unit 像素。
没有直接导入前端源码或伪造浏览器帧。

最终候选连续两次通过：

- `artifacts/browser-user-entry-shell-r5/summary.json`
- `artifacts/browser-user-entry-shell-r6/summary.json`

| 场景 | 实际操作和判据 | 结果 |
| --- | --- | --- |
| 创建 | 仅发起一次 Hook 命令，浏览器框选 320×160 区域，不返回执行第二次导入 | 自动出现 Live Unit |
| 网页滚动 | 实际文档 `scrollY=1400`，原区域底部位置为 `-1120`，已经离开源视口 | Live 中心仍为原区域绿色 `[34,197,94]` |
| 切换标签 | 激活红色背景的另一个标签，确认原文档 `document.hidden=true` | Live 没变成红色页面，仍为原绿色区域 |
| 不是冻结图片 | 分别比较初始、滚动后、标签切换后的已解码图片和截图哈希 | 三个阶段持续更新，不是保留首帧 |
| 通知 | 在原普通贴图的标准通知区点击“知道了” | 提示能关闭，等待继续，没有屏幕中央模态弹窗 |

## 不应扩大解释的范围

这次证明的是上述网页入口下，普通非虚拟化文档的原区域在滚动和切换标签后保持
绑定并更新。它不证明普通 Ctrl+2 的语义已改变，也不证明任意网站、被虚拟列表移除
的 DOM、DRM 视频或浏览器冻结页面都能继续更新。
当前网页提供方仍是只读、目标约 2 FPS，不是视频高帧率方案，也没有把网页按钮交互
一并宣布完成。日常 profile 的扩展启用和你的实际目标网站还需要按前述步骤复核。
