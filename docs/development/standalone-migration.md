# Otter 独立仓库边界与迁移兼容

本页保留独立开发所需的当前约定，不作为候选版本或验收结果清单。
旧版迁移执行记录、文件计数和候选哈希可通过本文件及原 `MIGRATION.md` 的 Git 历史查询；
它们不证明当前工作区、程序包或外部服务已经通过验收。

## 仓库与构建边界

- Otter 是独立 Git 仓库；正常前端与 EXE 构建不依赖旧 Neuro checkout。
- 代码通过 Git 获取，npm/Cargo 依赖按本仓库锁文件安装；不要复制旧 `node_modules`、
  Cargo target、前端输出、运行数据或旧仓库 `.git` 指针。
- Loom、Tea 等联合探针仍需要对应外部服务、包或仓库；单仓库编译通过不代表联合验收通过。
- 目录归属以[代码组织规范](CODE_ORGANIZATION.md)为准；开发入口与检查见
  [开发指南](../guide/development.zh-CN.md)，发布证据见[发布来源规范](../release/release-provenance.md)。

## 保持数据与协议兼容

独立 checkout 和目录调整不是数据迁移开关。不得因此改变应用标识、互斥锁、
已有会话格式、缓存范围或外部协议。需保留的旧命名见[更名兼容约定](RENAMING.md)。
普通启动仍使用现有应用身份与用户数据；手测前正常退出旧 Otter，不把第二实例
被拒绝误判为新候选启动失败，也不绕过单实例锁并发操作同一会话。

## 当前候选如何确认

- 从当前 Git HEAD、工作区差异和 `version-state.json` 确认源码身份，不沿用历史文档版本号。
- 对实际构建产物记录 SHA-256，并将测试证据绑定该候选；旧包通过不代表新包通过。
- 内部版本、脏工作区候选与正式公开发布分开报告，不将本地候选伪装成正式 release。
- 行数 ratchet 使用真实 Git 历史；不要为通过门禁改写历史基线或伪造提交。
- 编译、静态测试、浏览器检查、原生桌面、跨设备与外部服务验收分别报告；
  未运行、忽略及历史失败均不得写成当前通过。
